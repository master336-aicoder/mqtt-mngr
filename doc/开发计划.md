# mqtt-mngr 开发计划（V1.0 执行版）

> 依据：需求说明书 V1.2、技术设计说明书 V1.1、UI 设计说明书 V1.0（原型 `design/hifi/index.html` 为视觉验收基准）。
> 本文档为活文档：状态列随开发进度实时更新。

## 0. 环境基线与偏差声明

| 项 | 计划基线 | 实际环境 | 处理 |
|----|----------|----------|------|
| JDK | 17 | 21 | 以 `--release 17` 编译，兼容 |
| Kafka/EMQX Broker | 本地可用 | 无 Docker、无本地 Broker | MQTT E2E 用 **Moquette 嵌入式 Broker**（test 域）跑真实协议；Kafka 走错误路径验证 + 单测，接入真实集群留待联调 |
| 工程结构 | 多 Maven 模块 | — | **本期单模块分包**（`io.mngr.core/adapter/store/web`），M2 再物理拆模块；包边界按技术设计 §4 执行 |
| 前端 | Vite+Element Plus 构建 | — | **本期 Vue 3 全局构建（无打包）**：`static/` 下 SPA，token/组件复刻原型；M2 迁移 Vite 工程 |
| CLI (picocli) | M1 | — | 暂缓（延后至下一里程碑），REST 面优先 |

## 1. 本期交付范围（Do）

- FR-1 Server 管理：CRUD、H2/file 双模式存储、凭据 AES-GCM 加密、LAZY/EAGER/MANUAL、状态机+指数退避重连、健康探测、连接/断开
- FR-2 Topic 映射 CRUD（含通配、模板绑定）；Kafka Topic 列表/详情/创建/删除/扩容（allowAdminOps 门控）；EMQX clients/retained（配置了 API 凭据时）
- FR-3 发布：REST publish（同步/异步结果统一模型）、headers、QoS/retain/key、重试→缓冲→DLQ
- FR-4 订阅：注册/取消/暂停/恢复；守护进程形态下 sink=WS 调试流；背压有界队列；失败→DLQ
- FR-5 JSON Codec（泛型/类型化、信封降级、x-codec header）
- FR-6 消息模板：CRUD、版本、样例反推、静态关联、header/相似度自动匹配（指纹 LRU 缓存）、模板感知解析、匹配预览
- FR-7 管理：统一响应/错误码、Token 鉴权、审计（audit_log）、DLQ 浏览/重放、Micrometer/Prometheus 指标、WS 调试通道
- 前端：监控总览 / Server / Topic / 集群(只读为主) / 模板(编辑器+反推+匹配预览) / 收发调试台 / DLQ / 设置，按原型 1:1 复刻并接真实 API
- 验证：单测（模板反推/匹配/指纹/Codec/通配）+ @SpringBootTest 集成（Moquette 真协议 收→解析→归类→DLQ 全链路）+ 应用启动 curl 冒烟 + 浏览器 UI 走查

## 2. 明确不做（本期后）

CLI、代码生成、JSON Schema 导入导出、Kafka ACL/重分配/事务/Quota/日志截断、EMQX 会话/告警/限速/认证管理、转换链/脱敏、WebFlux/虚拟线程、多用户 RBAC、PostgreSQL 中心存储。

## 3. 里程碑任务分解与状态

| # | 任务 | 产出 | 状态 |
|---|------|------|------|
| T1 | 工程骨架：pom/配置/schema/启动类 | 可 `mvn compile` | ☐ |
| T2 | 领域模型 + SPI + 枚举 | core.model/spi | ☐ |
| T3 | 存储层：H2(MyBatis-Plus)+CredCipher+File(YAML/JSONL) 双实现 | store 包 | ☐ |
| T4 | JSON Codec + 模板引擎（反推/匹配/版本门禁） | codec/template | ☐ |
| T5 | Kafka Adapter（Producer/Consumer/Admin）| adapter.kafka | ☐ |
| T6 | MQTT Adapter（HiveMQ 5.0/3.1.1、共享订阅、EMQX MgmtClient）| adapter.mqtt | ☐ |
| T7 | 引擎：ServerManager 状态机/退避、Publisher、Subscriber、EventBus、Metrics | core.* | ☐ |
| T8 | Web 层：ApiResponse/异常/鉴权/REST 8 控制器 + WS | web/ws | ☐ |
| T9 | 前端 SPA（tokens+8 页+真实 API）| static | ☐ |
| T10 | 单测 + Moquette 集成测试 | test | ☐ |
| T11 | 构建启动、curl 冒烟、浏览器 UI 走查、修复 | 验收记录 | ☐ |

执行顺序 T1→T8 连续推进（T9 穿插），每个大项完成后增量编译；T10/T11 收口。

## 4. 验收清单（完成时逐项打勾）

- [ ] `mvn package` 通过；`java -jar` 启动成功
- [ ] REST：Server/Topic/Template CRUD 全通；错误配置返回校验码
- [ ] 注册错误 Kafka → 状态 DOWN + 退避重试计数可见；不崩溃
- [ ] 集成测试：Moquette 上 发布→订阅→模板命中(EXPLICIT/BOUND/SIMILARITY)→解析；必填缺失消息进 DLQ
- [ ] 模板：样例反推生成字段树；匹配预览返回得分排序
- [ ] WS：调试订阅实时收到消息帧
- [ ] UI：8 页全部真实数据渲染；发布一条消息后调试台可见
- [ ] 无库模式：servers.yaml 持久化生效
- [ ] 指标：/actuator/prometheus 含 mngr_* 计数

## 5. 风险

1. 依赖首次下载量大（Boot+Kafka+HiveMQ+Moquette），构建慢 —— 已确认中央仓库可达；
2. hivemq client 与 Boot netty 版本 —— 由 hivemq 传递依赖统一管理，不显式锁 Netty；
3. Windows 路径/编码 —— 源码 UTF-8，data-dir 相对路径。
