### 核心设计原则

- **SPI 解耦** — 协议适配器通过 SPI 接口（`ProtocolAdapter`、`ClusterOps`）注入，新增协议只需实现接口
- **双存储模式** — H2（关系型）和 File（YAML/JSON 文件）两种存储实现，通过 `mngr.store.mode` 切换
- **事件驱动** — `EventBus` 负责模块间松耦合通信
- **凭据安全** — 所有凭据 AES-256-GCM 加密存储，API 永不回显明文

## 5. 分层架构详解

### 5.1 Web 层（Controller）

职责：HTTP 协议处理、参数校验、响应封装

```java
@RestController
@RequestMapping("/api/v1/xxx")
@RequiredArgsConstructor
public class XxxController {
    private final XxxService xxxService;
    private final AuditHelper audit;

    @GetMapping
    public ApiResponse<Page<XxxEntity>> list(...) {
        return ApiResponse.ok(xxxService.list(...));
    }
}
```

**关键约定**：
- 所有响应使用 `ApiResponse<T>` 封装
- 审计操作通过 `AuditHelper.record()` 记录
- 危险操作通过 `MgmtGuard.requireDanger()` 保护

### 5.2 Service 层

职责：业务逻辑编排、事务管理

```java
@Service
@RequiredArgsConstructor
public class XxxService {
    private final XxxMapper xxxMapper;

    @Transactional
    public XxxEntity save(XxxEntity in) {
        // 业务逻辑
    }
}
```

### 5.3 Core 层

职责：核心领域逻辑、SPI 接口定义

**SPI 接口**：

| 接口 | 说明 |
|------|------|
| `ProtocolAdapter` | 协议适配（连接、发布、订阅） |
| `ClusterOps` | 集群管理操作 |
| `ConfigRepository` | 配置持久化 |
| `RuntimeRepository` | 运行时状态持久化 |
| `MessageCodec` | 消息编解码 |
| `TopicAdmin` | Topic 管理操作 |

### 5.4 Store 层

职责：数据持久化

- **H2 模式**：MyBatis-Plus Entity + Mapper，数据库文件存储
- **File 模式**：YAML/JSON 文件存储

### 5.5 Adapter 层

职责：协议实现

- `KafkaAdapter` — 实现 `ProtocolAdapter`，对接 Kafka Client
- `MqttAdapter` — 实现 `ProtocolAdapter`，对接 HiveMQ MQTT Client
- `KafkaClusterOps` — 实现 `ClusterOps`，Kafka 管理 API
- `EmqxClusterOps` — 实现 `ClusterOps`，EMQX 管理 API

## 6. 新增功能指南

### 6.1 新增 REST API

以新增「标签管理」为例：

**1. 定义实体**（`store/h2/entity/TagEntity.java`）：

```java
@Data
@TableName("tag")
public class TagEntity {
    @TableId(type = IdType.AUTO)
    private Long id;
    private String name;
    private LocalDateTime createdAt;
}
```

**2. 定义 Mapper**（`store/h2/mapper/TagMapper.java`）：

```java
@Mapper
public interface TagMapper extends BaseMapper<TagEntity> {
}
```

**3. 建表 SQL**（`schema.sql` 追加）：

```sql
CREATE TABLE IF NOT EXISTS tag (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  name VARCHAR(128) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

**4. Service 层**（`sys/TagService.java` 或独立包）：

```java
@Service
@RequiredArgsConstructor
public class TagService {
    private final TagMapper tagMapper;

    public List<TagEntity> list() {
        return tagMapper.selectList(null);
    }
}
```

**5. Controller 层**（`web/TagController.java`）：

```java
@RestController
@RequestMapping("/api/v1/tags")
@RequiredArgsConstructor
public class TagController {
    private final TagService tagService;
    private final AuditHelper audit;

    @GetMapping
    public ApiResponse<List<TagEntity>> list() {
        return ApiResponse.ok(tagService.list());
    }

    @PostMapping
    public ApiResponse<TagEntity> save(@RequestBody TagEntity in) {
        TagEntity saved = tagService.save(in);
        audit.record(in.getId() == null ? "CREATE" : "UPDATE", "TAG",
                String.valueOf(saved.getId()), null, saved);
        return ApiResponse.ok(saved);
    }
}
```

**6. 前端页面**（`app.js` 追加路由 + `index.html` 追加视图）

### 6.2 新增协议适配器

1. 实现 `ProtocolAdapter` 接口
2. 在 `CoreConfig` 中注册为 Bean（建议用 `@ConditionalOnProperty` 控制）
3. `ServerManager` 会根据协议类型自动选择适配器

### 6.3 新增菜单权限

1. 在 `schema.sql` 的菜单种子数据中追加 `INSERT INTO sys_menu`
2. 前端 `app.js` 的 `META` 对象中注册对应路由
3. 角色管理页面分配新菜单给角色

## 7. 数据库与 ORM

### 7.1 数据库表

| 表名 | 说明 |
|------|------|
| `server_config` | 服务连接配置 |
| `topic_config` | Topic 配置 |
| `msg_template` | 消息模板（复合主键 id+version） |
| `subscription` | 订阅配置 |
| `dlq_message` | 死信消息 |
| `audit_log` | 审计日志 |
| `sys_user` | 系统用户 |
| `sys_role` | 系统角色 |
| `sys_menu` | 系统菜单 |
| `sys_user_role` | 用户-角色关联 |
| `sys_role_menu` | 角色-菜单关联 |

### 7.2 MyBatis-Plus 约定

- 实体类使用 `@TableName` 指定表名
- 主键使用 `@TableId(type = IdType.AUTO)`
- 关联表（`sys_user_role`、`sys_role_menu`）使用复合主键，无需 `@TableId`
- 驼峰自动映射：`map-underscore-to-camel-case: true`
- 自定义 SQL 使用 `@Select` / `@Insert` 注解

### 7.3 数据库初始化

- `schema.sql` 在每次启动时执行（`spring.sql.init.mode=always`）
- 使用 `CREATE TABLE IF NOT EXISTS` 和 `WHERE NOT EXISTS` 保证幂等
- 种子数据：admin 用户、super_admin 角色、13 个菜单项


统一使用 `req()` 方法：

```javascript
// GET 请求
const res = await this.req('GET', '/api/v1/tags');

// POST 请求
const res = await this.req('POST', '/api/v1/tags', { name: 'test' });

// 响应格式: { code: 0, message: 'ok', data: ... }
if (res.code !== 0) {
  this.toast(res.message, 'error');
  return;
}
// 使用 res.data
```

每个页面由以下部分组成：

1. **视图模板** — `index.html` 中 `<section v-if="route==='xxx'">` 块

4. **表单提交** — `app.js` 中 `fmSubmit` 的 `case 'xxx'` 分支

## 9. 认证与权限

### 9.1 认证流程

```
客户端 → POST /api/v1/public/login (username + password)
       ← { token: "uuid-session-token", userInfo: {...} }

后续请求 → Header: X-Mngr-Token: uuid-session-token
        ← 正常响应

登出 → POST /api/v1/public/logout (Header: X-Mngr-Token)
```

### 9.2 双模式鉴权

`AuthFilter` 支持两种鉴权方式：

1. **Session Token**（登录获取）— 存储在 `SessionManager`（ConcurrentHashMap，24h TTL）
2. **静态 Token**（`mngr.auth.token`）— 配置非空时启用，用于 API 集成

白名单路径（无需鉴权）：
- `/api/v1/public/**`
- `/actuator/**`
- `/` 和 `/index.html` 等静态资源

### 9.3 RBAC 模型

```
User ──N:M──> Role ──N:M──> Menu
         (sys_user_role)  (sys_role_menu)
```

- **用户** — 登录凭据、基本信息
- **角色** — 权限集合的命名载体
- **菜单** — 树形结构，包含路由、图标、权限标识（`perm_code`）
- 登录时根据用户 → 角色 → 菜单，构建用户的菜单树和权限列表

### 9.4 UserContext

```java
// 在 Controller/Service 中获取当前用户
UserContext.UserInfo user = UserContext.get();
Long userId = user.userId();
String username = user.username();
```

通过 `AuthFilter` 在请求开始时设置 ThreadLocal，请求结束时清理。

## 10. 协议适配器扩展

```java
public interface ProtocolAdapter {
    Protocol protocol();                    // KAFKA / MQTT
    void connect(ServerConfig cfg);
    void disconnect(String serverId);
    PublishResult publish(PublishRequest req);

```

### 10.2 新增协议步骤

1. 在 `Protocol` 枚举中添加新协议
2. 创建 `XxxAdapter implements ProtocolAdapter`
3. 如需集群管理，创建 `XxxClusterOps implements ClusterOps`
4. 在 `CoreConfig` 中注册 Bean
5. 前端 `app.js` 中更新连接表单字段

## 11. 编码规范

### 11.1 Java

- 使用 Lombok 减少样板代码（`@Data`、`@RequiredArgsConstructor`、`@Slf4j`）
- 异常统一使用 `MngrException`，携带 `ErrorCode` 枚举
- 分页使用 `Page<T>` 封装
- 响应统一使用 `ApiResponse<T>`

### 11.2 错误码

| 错误码 | 枚举 | 含义 |
|--------|------|------|
| 1001 | `VALIDATION` | 参数校验失败 |
| 1002 | `NOT_FOUND` | 资源不存在 |
| 2001 | `DUP_NAME` | 名称重复 |
| 3001 | `CONN_FAILED` | 连接失败 |
| 3002 | `CONN_TIMEOUT` | 连接超时 |
| 401 | `UNAUTHORIZED` | 未认证 |
| 403 | `FORBIDDEN` | 无权限 |
| 8001 | `SERVICE_UNAVAILABLE` | 服务不可用 |
| 9999 | `INTERNAL` | 内部错误 |

### 11.3 前端

- CSS 变量统一主题色，BEM 命名
- 视图切换使用 `v-if="route==='xxx'"`
- API 调用统一 `req()` 方法
- 表单提交统一 `fmSubmit` 方法 + `case` 分支

## 13. 常见问题

### Q: 如何切换存储模式？

修改 `application.yml`：

```yaml
mngr:
  store:
    mode: file    # h2 → file
```

或使用 `--spring.profiles.active=file` 启动。

### Q: 如何添加新的配置属性？

1. 在 `MngrProperties` 中添加字段
2. 在 `application.yml` 中配置
3. 通过 `@ConfigurationProperties(prefix="mngr")` 自动绑定

### Q: 前端修改后如何生效？

前端文件在 `src/main/resources/static/` 下，修改后：
- 开发模式：`mvn spring-boot:run` 会自动加载
- 生产模式：重新 `bin/build.sh` 打包

### Q: 如何扩展审计日志？

所有写操作通过 `AuditHelper.record()` 记录。新增审计点：

```java
audit.record("ACTION", "OBJ_TYPE", "objId", beforeObj, afterObj);
```

### Q: H2 数据库如何升级？

H2 作为嵌入式数据库，版本由 Spring Boot BOM 管理。如需手动升级：
1. 备份 `data/db/mngr.mv.db`
2. 修改 `pom.xml` 中 H2 版本
3. 启动验证

### Q: 如何对接外部消息队列？

实现 `ProtocolAdapter` SPI 接口，参考 `KafkaAdapter` 和 `MqttAdapter` 的实现模式。
