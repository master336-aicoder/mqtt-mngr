## 1. 系统概述

mqtt-mngr 是 Kafka & EMQX 双协议统一消息管理客户端，提供：

- **服务连接管理** — Kafka / MQTT(EMQX) 双协议接入
- **Topic 管理** — 通配符订阅、Topic 浏览
- **消息模板** — JSON 结构推断、版本管理、自动匹配
- **收发调试** — 在线发布消息
- **订阅管理** — 启动/停止/暂停/恢复
- **死信 DLQ** — 失败消息查询、重放
- **集群管理** — Kafka 集群 / EMQX 集群远程运维
- **RBAC 权限** — 用户、角色、菜单权限管理

| 属性 | 值 |
|------|------|
| 技术栈 | Java 21 + Spring Boot 3.3.5 + MyBatis-Plus 3.5.7 |
| 数据库 | H2 (文件模式，MySQL 兼容) |
| 默认端口 | 8090 (HTTP) |
| 前端 | Vue 3 全局构建，无打包工具 |
| 产物 | `target/mngr-server.jar` (Spring Boot Fat JAR) |

## 3. 部署安装

### 3.1 编译打包

```bash
# 完整编译（含测试）
bin/build.sh

# 跳过测试快速打包
bin/build.sh --skip-test

# 清理后重新打包
bin/build.sh --clean --skip-test
```

产物位于 `target/mngr-server.jar`。

### 3.2 目录结构

部署后的推荐目录结构：

```
/opt/mqtt-mngr/
├── mngr-server.jar       # 从 target/ 复制
├── bin/                  # 运维脚本
│   ├── start.sh
│   ├── stop.sh
│   ├── restart.sh
│   ├── health.sh
│   └── inspect.sh
├── data/                 # 运行时数据（自动创建）
│   ├── db/               # H2 数据库文件
│   └── mngr-server.pid   # PID 文件
├── logs/                 # 日志目录（自动创建）
│   ├── mngr-server.log
│   ├── mngr-server-error.log
│   └── stdout.log
└── config/               # 可选：外部配置覆盖
    └── application-prod.yml
```

### 3.3 首次启动

```bash
# 前台启动（调试用）
bin/start.sh --foreground

# 后台启动
bin/start.sh

# 验证

```

### 3.4 Windows 部署

```cmd
bin\build.bat --skip-test

```

## 4. 配置说明

### 4.1 配置文件优先级

1. 命令行参数 `--key=value`（最高）
2. 环境变量
3. `config/application-prod.yml`（外部覆盖）
4. JAR 内置 `application.yml`（最低）

### 4.2 核心配置项

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|----------|--------|------|
| `server.port` | `MNGR_PORT` | `8090` | HTTP 服务端口 |
| `mngr.data-dir` | `MNGR_DATA_DIR` | `./data` | 数据目录 |
| `mngr.master-key` | `MNGR_MASTER_KEY` | `dev-master-key-change-me` | **凭据加密主密钥（生产必改）** |
| `mngr.auth.token` | `MNGR_AUTH_TOKEN` | `""` | 静态 API Token（非空启用） |
| `mngr.store.mode` | — | `h2` | 存储模式：`h2` / `file` |
| `mngr.allow-admin-ops` | — | `false` | 是否允许危险管理操作 |

### 4.3 性能调优

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `mngr.dispatch.queue-capacity` | `8192` | 订阅分发队列容量 |
| `mngr.dispatch.worker-per-sub` | `1` | 每个订阅的分发线程数 |
| `mngr.publish.buffer-capacity` | `10000` | 发布缓冲区容量 |
| `mngr.publish.overflow` | `DROP_OLDEST` | 缓冲区溢出策略：`DROP_OLDEST` / `DROP_NEWEST` / `BLOCK` |
| `mngr.publish.max-retries` | `3` | 发布最大重试次数 |
| `mngr.ws.send-queue-limit` | `2000` | WebSocket 发送队列限制 |

### 4.4 JVM 参数

通过 `MNGR_JVM_OPTS` 环境变量传入额外 JVM 参数。脚本默认配置：

```
-Xms256m -Xmx512m
-XX:+UseG1GC
-XX:+HeapDumpOnOutOfMemoryError
```

生产环境建议：

```bash
export MNGR_JVM_OPTS="-Xms512m -Xmx1024m -XX:MaxGCPauseMillis=200"
```

### 4.5 生产启动示例

```bash
export MNGR_PORT=8090
export MNGR_DATA_DIR=/data/mqtt-mngr
export MNGR_MASTER_KEY="your-256-bit-production-key-here"
export MNGR_AUTH_TOKEN="your-static-api-token"
export MNGR_JVM_OPTS="-Xms512m -Xmx1024m"

bin/start.sh
```

## 5. 服务管理

### 5.1 脚本一览

| 脚本 | 用途 | 用法 |
|------|------|------|
| `bin/build.sh` | 编译打包 | `bin/build.sh [--skip-test] [--clean]` |
| `bin/start.sh` | 启动服务 | `bin/start.sh [--foreground] [--profile=file]` |
| `bin/stop.sh` | 停止服务 | `bin/stop.sh [--force]` |
| `bin/restart.sh` | 重启服务 | `bin/restart.sh` |
| `bin/health.sh` | 健康检查 | `bin/health.sh` |
| `bin/inspect.sh` | 全面巡检 | `bin/inspect.sh` |

Windows 对应 `.bat` 脚本。

### 5.2 停止策略

1. 优先调用 Spring Boot Actuator `/actuator/shutdown`（graceful）
2. 等待 30 秒（可配置 `spring.lifecycle.timeout-per-shutdown-phase`）
3. 超时后发送 `SIGTERM`
4. 仍超时则 `SIGKILL`（`--force` 直接 SIGKILL）

### 5.3 开机自启（Linux systemd）

创建 `/etc/systemd/system/mqtt-mngr.service`：

```ini
[Unit]
Description=mqtt-mngr Message Management Platform
After=network.target

[Service]
Type=simple
User=mngr
Group=mngr
WorkingDirectory=/opt/mqtt-mngr
ExecStart=/usr/bin/java -Xms512m -Xmx1024m -XX:+UseG1GC \
  -jar /opt/mqtt-mngr/mngr-server.jar \
  --mngr.data-dir=/data/mqtt-mngr \
  --mngr.master-key=${MNGR_MASTER_KEY}
ExecStop=/bin/kill -SIGTERM $MAINPID
PIDFile=/data/mqtt-mngr/mngr-server.pid
Restart=on-failure
RestartSec=10
LimitNOFILE=65536

Environment=MNGR_MASTER_KEY=your-production-key
Environment=MNGR_PORT=8090

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable mqtt-mngr
sudo systemctl start mqtt-mngr
sudo systemctl status mqtt-mngr
```

## 6. 日常巡检

### 6.1 自动巡检

```bash
bin/inspect.sh
```

输出内容：

1. **进程状态** — PID、运行时长
2. **端口监听** — 8090 端口是否正常监听
3. **健康检查** — Actuator `/actuator/health` 响应
4. **磁盘空间** — 数据目录大小、可用磁盘
5. **日志错误** — 最近 ERROR 日志
6. **关键指标** — JVM 内存、HTTP 请求量、订阅数
7. **业务数据** — 概览统计

### 6.2 定时巡检（crontab）

```bash
# 每 5 分钟健康检查，异常时告警
*/5 * * * * /opt/mqtt-mngr/bin/health.sh || echo "mqtt-mngr DOWN at $(hostname)" | mail -s "ALERT" ops@example.com

# 每天 8:00 生成巡检报告
0 8 * * * /opt/mqtt-mngr/bin/inspect.sh > /var/log/mqtt-mngr-daily-inspect.log 2>&1
```

## 8. 数据备份与恢复

### 8.1 备份

H2 数据库文件位于 `data/db/mngr.mv.db`。

```bash
# 简单备份
cp data/db/mngr.mv.db /backup/mngr-$(date +%Y%m%d).mv.db

# 完整备份（含所有数据）
tar czf /backup/mqtt-mngr-$(date +%Y%m%d).tar.gz data/
```

> **注意**：建议在低峰期备份，或使用 H2 的 `BACKUP TO` SQL 命令在线备份。

### 8.2 恢复

```bash
# 停止服务
bin/stop.sh

# 恢复数据库文件
cp /backup/mngr-20260930.mv.db data/db/mngr.mv.db

# 启动服务
bin/start.sh
```

### 8.3 自动备份脚本

```bash
#!/bin/bash
# backup.sh — 建议 crontab 每日执行
BACKUP_DIR="/backup/mqtt-mngr"
mkdir -p "$BACKUP_DIR"
DATE=$(date +%Y%m%d)

cp data/db/mngr.mv.db "${BACKUP_DIR}/mngr-${DATE}.mv.db"

# 保留最近 7 天
find "$BACKUP_DIR" -name "mngr-*.mv.db" -mtime +7 -delete

echo "[$(date)] 备份完成: mngr-${DATE}.mv.db"
```

## 10. 故障排查

### 10.1 服务无法启动

| 现象 | 排查 |
|------|------|
| `Port 8090 already in use` | `netstat -ano \| grep 8090` 找到占用进程，kill 或改端口 |
| `Failed to execute database script` | 删除 `data/db/mngr.mv.db` 重建（**会丢失数据**） |
| `OutOfMemoryError` | 增大 `-Xmx`，检查 heapdump 文件 |
| 启动后立即退出 | 查看 `logs/stdout.log` 中的异常栈 |

### 10.2 登录问题

| 现象 | 排查 |
|------|------|
| 登录返回 9999 | 检查数据库是否正常初始化，查看 ERROR 日志 |
| Token 鉴权失败 | 确认请求头 `X-Mngr-Token` 正确 |
| 401 Unauthorized | Session 过期（24h TTL），重新登录 |

### 10.3 连接问题

| 现象 | 排查 |
|------|------|
| Kafka 连接超时 | 检查 bootstrap-servers 地址、网络连通性 |
| MQTT 连接失败 | 检查 broker URL、凭据是否正确 |
| 凭据解密失败 | 确认 `mngr.master-key` 与加密时使用的一致 |

### 10.4 性能问题

| 现象 | 排查 |
|------|------|
| 发布消息积压 | 检查 `mngr.publish.buffer-capacity` 和 `overflow` 策略 |
| WebSocket 断连 | 检查 `mngr.ws.send-queue-limit` 和网络状况 |
| 订阅分发延迟 | 增大 `mngr.dispatch.queue-capacity` 或 `worker-per-sub` |

## 11. 安全加固

### 11.1 必做项

1. **修改主密钥**
   ```bash
   export MNGR_MASTER_KEY="your-strong-256-bit-key"
   ```
   凭据使用 AES-256-GCM 加密存储，主密钥泄露将导致所有凭据可被解密。

2. **修改默认密码**
   首次登录后修改 admin 默认密码（admin123）。

3. **配置静态 Token 或 Session 鉴权**
   生产环境必须启用鉴权，不要将未鉴权的服务暴露到公网。

### 11.2 建议项

- 反向代理（Nginx）+ HTTPS
- 限制管理 API 访问 IP
- 定期审计日志检查
- `mngr.allow-admin-ops` 仅在需要时开启

### 11.3 危险操作保护

Kafka Topic 删除、Consumer Group 偏移重置、EMQX Retained 消息清除等危险操作需要：

1. `mngr.allow-admin-ops=true`
2. 请求参数 `confirm` 必须回显资源名称

## 12. API 接口清单

### 通用约定

- 基础路径：`/api/v1`
- 鉴权：Session Token（登录获取）通过 `X-Mngr-Token` 请求头传递
- 响应格式：

```json
{
  "code": 0,
  "message": "ok",
  "data": {},
  "requestId": "uuid"
}
```

- `code !== 0` 表示错误，常见错误码：
  - `1001` — 参数校验失败
  - `1002` — 资源不存在
  - `2001` — 重复名称
  - `401` — 未认证
  - `403` — 无权限
  - `9999` — 内部错误
